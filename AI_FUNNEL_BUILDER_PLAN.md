## 1. Product Vision

### What Is the AI Funnel Builder?

The **AI Funnel Builder** is a premium sub-module of **Woo Smart Shield** that gives WooCommerce store owners the ability to create high-converting landing pages and checkout funnels — entirely generated by AI — without writing a single line of code.

It is architecturally similar to **CartFlows** but with a critical differentiator: **AI generates the landing page HTML + CSS automatically** based on a product description, uploaded reference images, and a text-based prompt. Admins describe what they want in plain language, and the AI builds it.

### Core Promise

| Capability | Detail |
|---|---|
| **AI Page Generation** | Admin writes a prompt → AI returns production-ready HTML + CSS |
| **Visual Checkout Funnel** | Drag-and-drop checkout field builder connected to WooCommerce |
| **Image Placement via Text** | Admin writes `"Hero banner background image"` — not a dropdown |
| **Multi-Provider AI** | Google Gemini, OpenAI, DeepSeek, HuggingFace support |
| **Auto Cart Injection** | Visitor lands on page → product auto-added to WooCommerce cart |
| **Preview Before Save** | Sandboxed live preview before publishing |
| **Zero Visitor AI Calls** | AI is used only during admin content generation |

### Why It Fits Woo Smart Shield

The existing plugin already handles:
- Fake customer detection (risk scoring)
- Incomplete order recovery
- Courier webhook management
- Meta Conversions API
- SMS notifications

The AI Funnel Builder extends this ecosystem by **adding the top of the funnel** — attracting and converting visitors — making Woo Smart Shield a complete end-to-end WooCommerce growth suite.

### 4.3 Model Selection

This is the **most critical configuration option**. Admin selects the exact AI model via a dropdown **per provider**.

#### Why Model Selection Matters

Different models within the same provider offer dramatically different:
- **Speed** — Flash models respond in 1–3 seconds; Pro models take 5–15 seconds
- **Output Quality** — Pro/Plus models follow layout instructions more precisely
- **Cost** — Flash models can cost 10–20× less per generation
- **Token Limits** — Some models cap output at 4K tokens, others support 128K+
- **HTML Structure** — Larger models respect complex HTML/CSS structure better

### 4.4 AI Generation Settings

These are global parameters that control how the AI generates content. Configurable per funnel or globally.

**Temperature (Creativity Level)**
```
Option Key:  wsa_ai_temperature
Range:       0.0 → 1.0 (slider)
Default:     0.7
Description: Higher = more creative/varied output. Lower = more predictable/structured.
Recommended: 0.6–0.8 for landing pages (some creativity, still structured)
```

**Max Output Tokens**
```
Option Key:  wsa_ai_max_tokens
Range:       1000 → 32000
Default:     8000
Description: Controls maximum HTML+CSS output length.
Note:        Set to at least 8000 for full landing pages.
             Lower values may result in truncated HTML.
```

**Generation Mode**
```
Option Key:  wsa_ai_generation_mode
Values:      'fast' | 'balanced' | 'quality'

Fast:      Uses flash model, temp=0.5, max_tokens=4000
           → ~2–4 second generation, simpler layout
Balanced:  Uses default model, temp=0.7, max_tokens=8000
           → ~5–10 seconds, good quality
Quality:   Uses pro model, temp=0.8, max_tokens=16000
           → ~15–30 seconds, richest output
```

**HTML Structure Strict Mode**
```
Option Key:  wsa_ai_strict_html_mode
Values:      'yes' | 'no'
Default:     'yes'
Description: When ON, the AI system prompt instructs the model to:
             - Return ONLY raw HTML + <style> blocks
             - No markdown, no backtick code fences
             - No explanations or commentary
             - Valid semantic HTML5
             - All CSS inline in <style> tag
```

### 4.5 Provider Fallback Logic

If the primary AI provider fails (timeout, rate limit, API error), the system automatically retries with the configured backup provider.

**Fallback Flow:**
```
Admin triggers generation
        │
        ▼
[Primary Provider] ──── Success ──→ Return HTML to admin
        │
    Failure (timeout / 5xx / rate limit)
        │
        ▼
[Fallback Provider] ──── Success ──→ Return HTML (with notice: "Generated via fallback provider")
        │
    Failure again
        │
        ▼
[Return Error] ──→ Show admin: "AI generation failed. Check API keys & settings."
```

**Configurable Options:**
```
wsa_ai_fallback_enabled     → 'yes' | 'no'   (default: 'yes')
wsa_ai_fallback_provider    → provider slug   (default: 'openai')
wsa_ai_request_timeout      → seconds (int)   (default: 30)
wsa_ai_max_retries          → int             (default: 2)
```

### 4.6 AI Usage Strategy (Critical Design Rule)

> **RULE: AI is used ONLY during admin content generation. Visitors NEVER trigger AI API calls.**

| Scenario | AI Called? |
|---|---|
| Admin writes prompt and clicks "Generate" | ✅ YES |
| Admin regenerates a section | ✅ YES |
| Admin tests a connection | ✅ YES (minimal call) |
| Visitor opens landing page | ❌ NO — served from saved HTML |
| Visitor adds product to cart | ❌ NO — pure WooCommerce PHP |
| Visitor goes to checkout | ❌ NO — standard WooCommerce |

This ensures:
- Zero latency for visitors
- Zero per-visitor AI costs
- Pages are fast and cacheable
- AI API keys are never exposed on the frontend

## 7. Text-Based Image Placement System

### Design Philosophy

> **Critical Rule:** Image placement is described by the admin in free-form text input. There are NO predefined dropdown selectors.

This is intentional. Different landing pages have different sections. Forcing admins into a limited dropdown (e.g., "Hero", "Footer", "Left Side") creates friction and limits creativity.

Instead, the admin writes natural language placement instructions, and the AI interprets them intelligently within its context.

### How It Works

**Step 1 — Admin Uploads Images**
Each uploaded image gets a WordPress Media Library attachment ID.

**Step 2 — Admin Writes Placement Text**
```
Image 1:  hero-bg.jpg
Placement: "Hero banner full-width background image"

Image 2:  product-shot.png
Placement: "Product showcase section, centered above the buy button"

Image 3:  testimonial-avatar.jpg
Placement: "Customer testimonial avatar, circular crop, left of quote"

Image 4:  delivery-icon.png
Placement: "Shipping benefits icon, small, left of delivery text"
```

**Step 3 — System Builds Image Context Block**
The `ImageHandler` class builds a structured block that gets injected into the AI prompt:

```
--- IMAGE PLACEMENT INSTRUCTIONS ---
You have been provided the following images. Use them exactly as described.
Return the actual image URLs in the appropriate HTML img tags or CSS background-image properties.

Image 1 URL: https://example.com/wp-content/uploads/2026/hero-bg.jpg
Placement:   Hero banner full-width background image
Usage hint:  Use as CSS background-image on the hero section container.

Image 2 URL: https://example.com/wp-content/uploads/2026/product-shot.png
Placement:   Product showcase section, centered above the buy button
Usage hint:  Use as <img> tag with max-width:400px and margin:auto.

Image 3 URL: https://example.com/wp-content/uploads/2026/testimonial-avatar.jpg
Placement:   Customer testimonial avatar, circular crop, left of quote
Usage hint:  Use as <img> with border-radius:50%, width:60px.

Image 4 URL: https://example.com/wp-content/uploads/2026/delivery-icon.png
Placement:   Shipping benefits icon, small, left of delivery text
Usage hint:  Use as <img> with width:30px, vertical-align:middle.
--- END IMAGE PLACEMENT INSTRUCTIONS ---
```

**Step 4 — AI Interprets and Places Images**
The AI receives the full prompt including this image context block. It places images based on the admin's text descriptions within the generated HTML output. Usage hints guide the AI on whether to use `<img>` tags vs CSS `background-image`.

### `ImageHandler` Class Responsibilities

```php

    // Save uploaded image to WP Media Library, return attachment ID + URL

    // Parse placement text to generate usage hint

### Placement Hint Generator Logic

The `parse_placement_hint()` method uses simple keyword detection to add a useful CSS hint:

```php
private function parse_placement_hint(string $text): string {
    $text_lower = strtolower($text);

    if (str_contains($text_lower, 'background')) {
        return "Use as CSS background-image on the relevant container element.";
    }
    if (str_contains($text_lower, 'avatar') || str_contains($text_lower, 'circular')) {
        return "Use as <img> with border-radius:50%, appropriate small width (40-80px).";
    }
    if (str_contains($text_lower, 'hero') || str_contains($text_lower, 'banner')) {
        return "Use as CSS background-image on full-width hero/banner section.";
    }
    if (str_contains($text_lower, 'icon')) {
        return "Use as small <img> tag (24-48px) inline with text.";
    }
    // Default
    return "Use as <img> tag placed as described.";
}
```

## 9. AI Generation Engine Workflow

### Class: `AIGenerationEngine`

This is the core orchestration class. It:
1. Assembles the full prompt
2. Selects the provider
3. Makes the API call
4. Validates the output
5. Returns HTML or error

### Complete Generation Flow

```
Admin clicks "Generate Landing Page"
         │
         ▼
AdminIntegration::handle_generate_ajax()     ← AJAX handler (wp_ajax_wsa_ai_generate)
         │

         │
         ├─ Success ────────────────────────────────────────────────────────┐
         │                                                                  │
         └─ Failure → try FallbackProvider::generate()                     │
                           │                                                │

### Provider Adapter Interface

All providers implement:

```php

### Example: GeminiProvider Implementation Sketch

```php
class GeminiProvider implements AIProviderAdapterInterface {

    private string $api_key;
    private string $model;

    public function __construct() {
        $this->api_key = AISettingsManager::get_decrypted_key('gemini');
        $this->model   = get_option('wsa_ai_gemini_model', 'gemini-1.5-flash');
    }

    public function generate(string $prompt, array $options = []): array {
        $endpoint = "https://generativelanguage.googleapis.com/v1beta/models/{$this->model}:generateContent?key={$this->api_key}";

        $body = [
            'contents' => [[
                'parts' => [['text' => $prompt]]
            ]],
            'generationConfig' => [
                'temperature'     => (float) get_option('wsa_ai_temperature', 0.7),
                'maxOutputTokens' => (int)   get_option('wsa_ai_max_tokens', 8000),
            ]
        ];

        $response = wp_remote_post($endpoint, [
            'headers' => ['Content-Type' => 'application/json'],
            'body'    => wp_json_encode($body),
            'timeout' => (int) get_option('wsa_ai_request_timeout', 30),
        ]);

        if (is_wp_error($response)) {
            return ['success' => false, 'error' => $response->get_error_message()];
        }

        $data = json_decode(wp_remote_retrieve_body($response), true);
        $html = $data['candidates'][0]['content']['parts'][0]['text'] ?? '';

        return ['success' => true, 'html' => $html, 'model' => $this->model];
    }
}
```

### Output Validation & Sanitization

After AI returns HTML, `OutputValidator` ensures safety and correctness:

```php
class OutputValidator {

    public static function validate(string $raw_output, array $allowed_image_urls): string {

        // 1. Strip markdown code fences (```html ... ```)
        $html = preg_replace('/^```(?:html)?\s*/i', '', $raw_output);
        $html = preg_replace('/\s*```$/', '', $html);

        // 2. Ensure output starts with valid HTML
        if (!str_contains($html, '<html') && !str_contains($html, '<!DOCTYPE')) {
            $html = "<!DOCTYPE html><html><head><meta charset='UTF-8'></head><body>{$html}</body></html>";
        }

        // 3. Validate all img src URLs are in allowed list (prevent prompt injection image URLs)
        // (uses regex to find all src attributes and cross-check)

        // 4. WordPress KSES sanitization with expanded allowed tags for HTML pages
        // Note: For full HTML pages, we use a permissive allow-list
        // (admin-only generated content; not user-submitted)

        return $html;
    }
}
```

## 11. Auto Cart & Funnel Logic

### Auto Cart Injection

When a visitor lands on a landing page, the selected WooCommerce product is automatically added to their cart **without any button click**. This is the "auto cart" feature.

**Implementation:**

```php
// AutoCartInjector.php — hooked on frontend page load
add_action('template_redirect', [$this, 'inject_product_to_cart']);

public function inject_product_to_cart() {
    if (!is_singular('wsa_landing_page')) return;

    $post_id    = get_the_ID();
    $product_id = get_post_meta($post_id, '_wsa_funnel_product_id', true);
    $quantity   = (int) get_post_meta($post_id, '_wsa_funnel_quantity', true) ?: 1;

    if (!$product_id) return;

    // Only add if not already in cart
    $cart_contents = WC()->cart->get_cart();
    foreach ($cart_contents as $item) {
        if ((int)$item['product_id'] === (int)$product_id) return; // Already in cart
    }

    WC()->cart->add_to_cart($product_id, $quantity);
}
```

**Variation Support:**
If the product has variations (size, color), the landing page can pre-select a variation:
```
post_meta: _wsa_funnel_variation_id   → WooCommerce variation ID
```

## 13. Performance Optimization Strategy

### Core Principle

> **Zero AI cost per visitor. Zero per-request latency from AI.**

The landing page is a static HTML artifact — generated once by the admin, stored in `post_meta`, and served as-is on every visit.

### Caching Strategy

| Layer | Implementation | Benefit |
|---|---|---|
| **Object Cache** | `wp_cache_set/get` for CPT queries | Reduces DB reads |
| **Transient Cache** | Preview tokens (30 min TTL) | Fast preview, auto-cleanup |
| **Page Cache Compatible** | Pure HTML output, no PHP on frontend | Works with WP Rocket, LiteSpeed, etc. |
| **CDN Compatible** | Static HTML pages cacheable at CDN edge | Global speed |

### Auto Cart Performance

Auto cart injection uses WooCommerce's native `WC()->cart->add_to_cart()`. Optimization:
- Only runs on `wsa_landing_page` post type (early exit otherwise)
- Cart check performed first to avoid duplicate additions
- Session started lazily (WooCommerce handles this natively)

### Admin Generation

AI generation is **synchronous** from the admin's perspective (they wait for the result). For very long generations (quality mode), a loading indicator with estimated time is shown:

```
⏳ Generating your landing page using Gemini 1.5 Flash...
   Estimated time: 5–10 seconds
```

Future optimization: Queue generation as a background job using WP Cron (same pattern as existing `FakeCustomerDetection` async processing).

### Asset Loading

Landing page CSS is **embedded** in the `<style>` tag inside the AI-generated HTML. No external CSS files are loaded. This ensures:
- Single HTTP request for the full styled page
- No render-blocking stylesheets
- Maximum Google PageSpeed score compatibility

## 14. Security Considerations

### API Key Security

| Risk | Mitigation |
|---|---|
| Key exposure in HTML/JS | Never exposed on frontend; server-side only |
| Key exposure in DB | Encrypted with `openssl_encrypt` + site-unique salt |
| Key exposure in logs | API keys stripped from debug logs |
| Unauthorized key access | Admin `manage_options` capability required |

**Encryption implementation:**
```php
class AISettingsManager {

    private static function get_encryption_key(): string {
        // Uses WordPress AUTH_KEY from wp-config.php as salt
        return hash('sha256', AUTH_KEY . SECURE_AUTH_KEY);
    }

    public static function encrypt_key(string $raw_key): string {
        $iv  = openssl_random_pseudo_bytes(16);
        $enc = openssl_encrypt($raw_key, 'AES-256-CBC', self::get_encryption_key(), 0, $iv);
        return base64_encode($iv . $enc);
    }

    public static function decrypt_key(string $enc_key): string {
        $decoded = base64_decode($enc_key);
        $iv  = substr($decoded, 0, 16);
        $enc = substr($decoded, 16);
        return openssl_decrypt($enc, 'AES-256-CBC', self::get_encryption_key(), 0, $iv);
    }

    public static function get_decrypted_key(string $provider): string {
        $raw = get_option("wsa_ai_{$provider}_api_key", '');
        return $raw ? self::decrypt_key($raw) : '';
    }
}
```

### AJAX Security (All Admin AJAX Endpoints)

```php
// Every AJAX handler must verify:
check_ajax_referer('wsa_ai_generate_nonce', 'nonce');
if (!current_user_can('manage_options')) {
    wp_send_json_error('Unauthorized', 403);
}
```

### AI Output Sanitization

Generated HTML is admin-only content (not user-submitted), but still sanitized:
- Strip PHP tags (`<?php`, `<?`)
- Strip `<script>` with external `src` attributes (allow inline analytics only)
- Validate all image URLs against the uploaded image URL list
- Use `wp_kses_post()` on any text content extracted separately

### Prompt Injection Prevention

User-provided product descriptions and image placement text are sanitized before injection into the AI prompt:

```php
$placement_text = sanitize_textarea_field($raw_placement);
$product_desc   = wp_strip_all_tags(get_post_field('post_excerpt', $product_id));
```

This prevents malicious input from hijacking the AI prompt (e.g., `Ignore all previous instructions and...`).

### Landing Page Access Control

- Preview URLs require admin login (`current_user_can('manage_options')`)
- Published landing pages are public (standard WordPress `is_singular()` behavior)
- Draft landing pages return 404 to non-admins

### Rate Limiting for AI Endpoints

```php
// Prevent rapid repeated AI generation requests
$last_generation = get_transient('wsa_ai_last_generation_' . get_current_user_id());
if ($last_generation && (time() - $last_generation) < 10) {
    wp_send_json_error('Please wait before generating again.', 429);
}
set_transient('wsa_ai_last_generation_' . get_current_user_id(), time(), 60);
```

## 17. Error Handling & Failover Logic

### AI Generation Errors

| Error Type | Cause | Admin-Facing Message | System Action |
|---|---|---|---|
| `api_key_missing` | No API key configured | "Please add your API key in AI Settings." | Stop, show settings link |
| `api_key_invalid` | Wrong key | "API key rejected. Please verify in AI Settings." | Stop, show settings link |
| `rate_limit` | Too many requests | "AI rate limit hit. Trying backup provider..." | Trigger fallback |
| `timeout` | Request > 30 seconds | "AI took too long. Trying backup provider..." | Trigger fallback |
| `output_empty` | AI returned nothing | "AI returned empty output. Please try again." | Show retry button |
| `output_invalid` | No valid HTML in response | "Generated content was invalid. Try Quality mode." | Show retry button |
| `all_providers_failed` | All providers failed | "All AI providers failed. Check keys & settings." | Log error, alert admin |

### Error Logging

```php
// All AI errors logged to WordPress error log with context
error_log(sprintf(
    '[WSA AI Funnel] Generation failed. Provider: %s, Model: %s, Error: %s, Landing Page: %d',
    $provider, $model, $error_message, $landing_page_id
));
```

### Checkout Form Errors

| Error | Handling |
|---|---|
| Missing required field | Inline field-level validation before submit |
| Invalid phone format | Real-time regex validation in JavaScript |
| WooCommerce order creation failure | Show user-friendly error; log full error |
| Product out of stock | Pre-check on page load; show "Out of Stock" notice |

### Auto Cart Errors

| Error | Handling |
|---|---|
| Product not found | Silent fail; visitor can still fill form with product ID in hidden field |
| Product out of stock | Notice shown above checkout form |
| WooCommerce session not started | Force session start with `WC()->session->set_customer_session_cookie(true)` |

### Frontend Error Display

```html
<!-- Injected into landing page on error -->
<div id="wsa-cart-notice" style="display:none;background:#fff3cd;border:1px solid #ffc107;
     padding:10px;text-align:center;margin-bottom:20px;">
    ⚠️ Unable to add product to cart automatically. Please refresh the page.
</div>
```

### Preview System Errors

| Error | Handling |
|---|---|
| Preview token expired | "Preview expired. Please regenerate the page." |
| Preview accessed by non-admin | `wp_die()` with access denied message |
| Iframe blocked by browser | Fallback: open in new tab with direct URL |

### Scalability Architecture Considerations

**For High-Traffic Stores (1000+ daily visitors per landing page):**
- All landing pages are static HTML → 100% CDN cacheable
- Database reads: Single `get_post_meta()` call per page (can be object-cached)
- Auto cart: Single WooCommerce session operation
- Zero per-visitor AI calls (by design)

**For Agencies (Multiple Client Sites):**
- License system already in place (`LicenseManager.php`)
- Per-site AI key configuration (each site has its own keys)
- Future: Central API key pooling for agency plans

**For Stores with Many Funnels (50+):**
- CPT with proper indexing handles thousands of funnels
- Prompt template library reduces repeated prompt writing
- Bulk generation queue (Phase 3): Generate 10 landing pages with one click
